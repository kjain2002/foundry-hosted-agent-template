🔑 Key insight: the container is created by the client (user identity) but used & executed inside Foundry. The managed identity never creates a container — that sidesteps the RBAC 403 that blocked v10.

🧩 The puzzle pieces (what makes v13 work)

📜 Bundled skill (direct injection)
  • pptx-generation SKILL.md read at startup
  • Template mode or no-template style mode
  • Immune to the isolated-project skills-API write gap
🧰 Foundry Toolbox for OAuth MCP
  • Hosted runtime can't surface consent from a raw code-attached MCP
  • Toolbox brokers consent → oauth_consent_request
  • Client renders the sign-in link
⚙️ Real Code Interpreter
  • Must use the real SDK tool (dict tool = silent no-op)
  • disable_instrumentation() avoids the JSON-serialize crash
  • Bound to an explicit container_id
📦 Client-created container
  • Created at the project-scoped OpenAI endpoint
  • Passed per request as USE_CONTAINER_ID=cntr_…
  • Enables real file download (PK-valid .pptx)
🔎 Observability hacks (new in v13)
  • SKILL_USED: marker → skill badge
  • Container file-delta → “CI produced file” evidence
  • Per-turn debug JSON in ui/logs/
🔒 Private networking
  • Foundry publicNetworkAccess=Disabled
  • VPN / private endpoint required to reach it
  • Private DNS resolves to a 192.168.x address
